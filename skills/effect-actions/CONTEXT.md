# Context

Vocabulary for `@gjermundgaraba/effect-actions`. The docs, the code, and the tests use these
words with these meanings. Module names and Effect's own terms (`HttpApi`, `Tool`, `Toolkit`,
`McpServer`, `Command`) mean what their modules say.

## Terms

- **Action**: one contract. A name, a description, an input schema, a success schema, declared error schemas, `access`, `auth`, its declared checks, and tool `hints`. Holds no behavior. Made by `Action.make`.
- **Access**: `"read"` or `"write"`, required on every action and kept as a literal. States what the action does to its resource. Read by an implementation's `authorize`, and the only source of a tool's read-only hint.
- **Auth**: who may call an action, required on every contract: `auth: "public"`, a **public action**, which anyone may call, or the identity service a caller must have, such as `auth: CurrentActor`, a **protected action**. Every surface enforces it: a remote one through authentication, a local one by requiring the host to provide that identity on every call.
- **Identity**: the service a protected action declares, `Context.Service` only, so a contract importing it stays browser-safe. One per action, and one per remote surface; a tenant or other request context is an ordinary request-time requirement. A **trusted identity** is one only a host supplies on a local surface, such as an operator's on an admin CLI, typed apart from what a verifier returns, so no token names it.
- **Handler**: a function from decoded input to an Effect of decoded success, failing only with the action's declared errors and the built-in ones. The services it yields, and an authorizer's and a check's per call, are **request-time requirements**, supplied per call: over HTTP by authentication and router middleware around the surface; on a local surface by the host.
- **Implementation**: actions bound to their handlers and, where any is protected, their authorizer, one per `Action.implement` call. Nominal. Every surface that runs handlers takes an implementation or a list; its [selection rules](guarantees.md#names) determine which actions are exposed, each keeping its implementation's handlers, builder and authorizer.
- **Builder**: the Effect passed to `implement` instead of a plain handler or record. It runs once per layer graph, however many surfaces serve its implementation, and once per invocation of a local CLI command: [guarantees.md](guarantees.md#dependency-lifetimes). The services it yields are **build-time requirements**, or startup services, resolved when its layer is built. An authorizer may be built the same way, the Effect returning it instead ([Action.md](Action.md#built-authorization)); so are a check, by `Layer.effect`, and a verifier, by `Authentication.layer`.
- **Layer graph**: the layers Effect builds together, sharing one memo map, so each is built once however many layers use it. `HttpRouter.serve` and `Testing.layer` build their routes in a graph of their own, which reuses what the graph around them has already built, and `Layer.fresh` builds its layer in a new one. `HttpRouter.provideRequest` also builds the layer it provides in a graph of its own, which reuses what the routes' graph has already built. Builders and your own services follow it alike: [dependency lifetimes](guarantees.md#dependency-lifetimes).
- **Host**: the application that serves the surfaces: it builds their layers, provides their services and middleware, and runs the server, subprocess or CLI.
- **Surface**: where callers reach actions: HTTP routes, an MCP endpoint, a Toolkit, a CLI command, a client in process. Each serves the implementations passed to it and validates only the names it serves. A **remote surface** has callers it authenticates (`ActionHttp.layer`, `ActionMcp.layerHttp`). A **local surface** has none (`ActionToolkit`, a local `ActionCli` command, `ActionMcp.runStdio`, `Action.client`): nothing authenticates, and the host provides the identity.
- **Binding**: the value `ActionHttp.make` returns, `{ actions, errors, prefix, authentication, api }`, typed `ActionHttp.Binding`. Plain data shared by the server and every client. It decides what HTTP serves: `ActionHttp.layer` serves its actions among the implementations given. No other surface has one.
- **Client**: one method per action, `client.<action>(input)`, taking its input and answering its decoded success, or failing with its declared errors and the built-in ones as decoded values. `ActionHttp.client` calls a binding's routes and `Testing.mcpClient` an endpoint's tools; `Action.client` calls implementations in process, through the dispatch every surface runs, encoding then decoding the input, the success and the failure as a wire carries them: a local surface for code.
- **Authorizer**: `authorize`, an Effectful function of the selected action, which each implementation of protected actions states, `Action.implement(actions, handlers, { authorize })`, and every surface serving them runs. It runs only for protected actions, after authentication and input decoding, before the checks and the handler, and succeeds or fails with a refusal: [guarantees.md](guarantees.md#authorization). `Action.allowAll` lets every authenticated caller call. An implementation of public actions alone states none.
- **Check**: an operational rule declared on contracts, such as a rate limit: `Action.Check`, a transport-free declaration of the one error it may fail with and the request-time services it may read, listed in an action's `checks`, whose errors then include that error. A native layer implements it once, `Layer.succeed` with its callback or `Layer.effect` building it once per layer graph, which every surface serving such an action requires at startup. It runs for public and protected actions alike, after the authorizer and before the handler: [guarantees.md](guarantees.md#authorization).
- **Authentication descriptor**: what `Authentication.make` returns: a named, browser-safe declaration of how a remote caller proves an identity, by one native scheme, Bearer unless it names another. A binding and an MCP endpoint serving protected actions name it, `authentication: Login`. Its name identifies the one provider that satisfies it.
- **Authentication provider**: what `Authentication.layer` returns for a descriptor: the server-only verifier, built once per layer graph, and the discovery of an OAuth protected resource. Every HTTP or MCP layer serving protected actions requires it, and it authenticates their requests before decoding them. Action-level authorization is the authorizer's; record-level checks belong in handler data access ([authorization](guarantees.md#authorization)).
- **Layer middleware**: native `HttpApiMiddleware` given to `ActionHttp.layer(http, apps, { middleware })`, run around every route the layer serves, inside authentication and outside decoding. HTTP only.
- **Mixed endpoint**: an MCP endpoint serving public and protected tools on one URL. Discovery and public tools' calls answer anyone; every other request authenticates before the endpoint decodes it ([ActionMcp.md](ActionMcp.md#rules)).
- **Declared error**: an error schema listed on an action, in its `errors` or by one of its checks. Handlers may fail with it, and so may the check declaring it. HTTP sends its JSON encoding with its `httpApiStatus`, 422 without one; MCP returns the same JSON as an `isError` result; the Toolkit returns it as a failure result; a CLI command prints the same JSON on stderr, failing with Effect CLI's `UserError`, whose `cause` it is.
- **Built-in errors**: `Action.InvalidInput` (400), `Action.Unauthenticated` (401) and `Action.Forbidden` (403), tagged errors with body `{ _tag, message }` and a default `message`; an `InvalidInput` may also list `issues`, each a `path` into the input and a `message`, and a `Forbidden` the OAuth `scopes` a call lacks. The library produces them, and every surface declares them: [guarantees.md](guarantees.md#wire-behavior).
- **Refusal**: `Action.Refusal`, `Unauthenticated | Forbidden`. What authentication or an authorizer refuses a caller with instead of letting a handler run, and all an authorizer may fail with. A **step-up refusal** is one an OAuth client acts on, `Unauthenticated` or a `Forbidden` naming `scopes`. Its HTTP status, challenge, and the exception for an MCP response that has already started follow the [authorization rules](guarantees.md#authorization).
- **Text field**: a top-level string field of an action's encoded success, such as a page of Markdown, that the action's `text` hint names for its MCP tool. MCP sends it once, raw, as the first text block, then the JSON of the rest as the second, and sends that tool's results without structured content and lists it without an output schema. Every other surface serves the whole success.
