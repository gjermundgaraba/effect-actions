# Context

Vocabulary for `@gjermundgaraba/effect-actions`. The docs, the code, and the tests use these
words with these meanings. Module names and Effect's own terms (`HttpApi`, `Tool`, `Toolkit`,
`McpServer`, `Command`) mean what their modules say.

## Terms

- **Action**: one contract. A name, a description, an input schema, a success schema, declared error schemas, `access`, and tool `hints`. Holds no behavior. Made by `Action.make`.
- **Access**: `"read"` or `"write"`, required on every action and kept as a literal. States what the action does to its resource. Read by an implementation's `before` hook, and the only source of a tool's read-only hint.
- **Handler**: a function from decoded input to an Effect of decoded success, failing only with the action's declared errors and the built-in ones. The services it yields, and a `before` hook's, are **request-time requirements**, supplied per call: over HTTP by router middleware around the surface, authentication included; on a local surface by the host.
- **Implementation**: actions bound to their handlers and their `before` hook, one per `Action.implement` call. Nominal. Every surface that runs handlers takes an implementation or a list; its [selection rules](guarantees.md#names) determine which actions are exposed.
- **Builder**: the Effect passed to `implement` instead of a plain handler or record. It runs once per build of the host's layers, however many surfaces serve its implementation, and once per invocation of a local CLI command: [guarantees.md](guarantees.md#dependency-lifetimes). The services it yields are **build-time requirements**, resolved when the host's layers are built. A `before` hook may be built the same way, the Effect returning the hook instead ([Action.md](Action.md#built-hooks)), and `Authentication.make` takes one returning the per-request authentication ([Authentication.md](Authentication.md#api)).
- **Host**: the application that serves the surfaces: it builds their layers, provides their services and middleware, and runs the server, subprocess or CLI.
- **Surface**: where callers reach actions: HTTP routes, an MCP endpoint, a Toolkit, a CLI command, a client in process. Each serves the implementations passed to it and validates only the names it serves. A **local surface** has no remote caller (`ActionToolkit`, a local `ActionCli` command, `ActionMcp.runStdio`, `Action.client`): nothing authenticates, and the host provides the identity.
- **Binding**: the value `ActionHttp.make` returns, `{ actions, errors, api }`, typed `ActionHttp.Binding`. Plain data shared by the server and every client; `ActionHttp.layer` serves it. No other surface has one.
- **Client**: one method per action, `client.<action>(input)`, taking its input and answering its decoded success, or failing with its declared errors and the built-in ones as decoded values. `ActionHttp.client` calls a binding's routes and `Testing.mcpClient` an endpoint's tools; `Action.client` calls implementations in process, through the dispatch every surface runs, encoding then decoding the input, the success and the failure as a wire carries them: a local surface for code.
- **`before` hook**: an Effectful function of the selected action, bound to an implementation and run by every surface serving it. Every implementation has one, `Action.allowAll` when no action-level rule applies. It runs after input decoding and before the handler, and succeeds, or fails with a refusal or with an error every action of its implementation declares, such as a rate limit: [guarantees.md](guarantees.md#authorization).
- **Authentication**: router middleware the host provides around HTTP surfaces, such as `Authentication.make`: it establishes the caller's identity before decoding. Action-level authorization is the `before` hook's; record-level checks belong in handler data access ([authorization](guarantees.md#authorization)).
- **Declared error**: an error schema listed on an action. Handlers may fail with it, and a `before` hook may when every action of its implementation declares it. HTTP sends its JSON encoding with its `httpApiStatus`, 422 without one; MCP returns the same JSON as an `isError` result; the Toolkit returns it as a failure result; a CLI command prints the same JSON on stderr, failing with Effect CLI's `UserError`, whose `cause` it is.
- **Built-in errors**: `Action.InvalidInput` (400), `Action.Unauthenticated` (401) and `Action.Forbidden` (403), tagged errors with body `{ _tag, message }` and a default `message`; a `Forbidden` may also name the OAuth `scopes` a call lacks. The library produces them, and every surface declares them: [guarantees.md](guarantees.md#wire-behavior).
- **Refusal**: `Action.Refusal`, `Unauthenticated | Forbidden`. What authentication or a `before` hook refuses a caller with instead of letting a handler run. A hook may also fail with an error every action of its implementation declares, which is not a refusal and never steps up. A **step-up refusal** is one an OAuth client acts on, `Unauthenticated` or a `Forbidden` naming `scopes`. Its HTTP status, challenge, and the exception for an MCP response that has already started follow the [authorization rules](guarantees.md#authorization).
- **Text field**: a top-level string field of an action's encoded success, such as a page of Markdown, that an MCP server's `tools` option names for the action's tool. MCP sends it once, raw, as the first text block, and leaves it out of the structured content and of the tool's listed output schema. Every other surface serves the whole success.
