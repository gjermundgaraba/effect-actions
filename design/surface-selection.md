# Surface selection

MCP endpoints, Toolkits, CLI aggregates and `Action.client` take `actions`, the actions they serve among the implementations given, as HTTP's binding lists its own: one way to keep an action off any surface, its list. Each surface narrows every implementation to the listed actions it holds and leaves out, unbuilt, an implementation holding none, since passing every implementation and listing the tools is the common case. A listed action nothing given holds is refused, as a stale list. Rejected: a flag on the contract, 0.8.0's `mcp: false`, since a contract says nothing about where it is served; and `Action.share`, now removed, which repeated the list per implementation and built an implementation whose actions were all left out.

Selection never changes policy: an action keeps its `caller` and authorizer wherever it is served. A caller trusted on one surface, such as an admin CLI's, is an identity only the host supplies there, typed apart from what a verifier returns, which the same authorizer admits. Lost: a trusted call still builds and runs the authorizer. Rejected: a `withAuthorization` export replacing a surface's policy, which would make authorization replaceable by whoever builds a surface.

An option that may be absent narrows nothing: each surface takes one signature inferring the options' type, and types what it serves as the listed actions only where `actions` is always present, since otherwise it may serve every action at run time. Rejected: overload pairs, one for options without `actions` and one with, which refused a reusable options value whose `actions` is optional, `ActionToolkit`'s own `Options` type included. So `needsApproval`'s `call` is typed by every action of the implementations, and `ActionCli.make` and `ActionCli.remote` type `commands` by every action they take, so one record serves aggregates of several selections, where typing it by the listed actions threw `Unknown commands`. `ActionHttp.layer` reads `actions` and `middleware` by the same rule, and `ActionHttp.make` reads `error` so: options that may leave it out declare it or none, so clients decode it and no layer middleware may fail with it, where declaring none had clients miss an error the binding did declare. A middleware's error counts as declared only as a slot of that one schema in one error list of fixed length, as an array may be empty, a slot of a union may hold another schema, and a union of lists may select another list; the built-ins, which every endpoint declares, are always allowed. `make` takes public-only actions alone or with options, two forms, as a conditional rest parameter loses the `const` tuple of errors.

`Serving`, which types what a surface owes, tests an action against the whole list before comparing it pairwise, and skips the pairwise test for a name the list lacks, binding `A` by `infer A extends Action.Any`: measured on TypeScript 7.0.2 and Effect 4.0.0 over 400 actions of four errors, a toolkit of all of them took 2.30M instantiations pairwise, and 0.43M testing each action against `Action.Any` alone, where it takes 0.54M now, 1% above its cost without `actions`; an HTTP layer of the full binding went from 2.31M to 0.54M, and one of 900 actions, too deep to check before, compiles in 2.26M. A command for an action a selection leaves out is unused rather than refused: one record of commands serves aggregates of several selections, each owing what its listed actions owe. `ActionHttp.make` and `ActionRpc.make` take two forms, not one with a conditional rest parameter, through which TypeScript infers no `const` tuple of errors, so explicit options naming errors require the argument; the first takes public actions by its constraint, which a helper generic in them meets. A last overload is reached only when those fail, since TypeScript reports a call matching none by the last one's error alone: protected actions without options are told to name their authentication rather than to be public. `layer` reads its options apart, so the middleware or actions an options type names are never typed as installed or selected where the options are left out.
