# Verifier errors

A descriptor declares what its verifier may fail with besides a refusal, `Authentication.make(name, identity, { error })`, one schema or a list, held as a list on the descriptor: a verifier fails with a refusal or one of them. Every protected endpoint of a binding naming the descriptor declares them, at the status `declared` gives an action's errors, so the native client decodes them and the OpenAPI document shows them; a public endpoint, which nothing verifies, does not. The provider sends one from a route, an MCP endpoint and `protect` through one encoder, `declaredResponse`, its JSON by the first declared schema accepting it, with that schema's status, `no-store`, challenged only as a 401, and `refusalResponse` sends it as they do, given the descriptor; a test holds the four answers equal. This reverses a verifier failing with an `HttpServerResponse`, "for a status or header that varies per refusal", and the rule "map a verifier's failure to a refusal": every downstream use of the response was a declared error in disguise, the clankerauth SDK's 503 for an issuer it cannot reach and clankerauth's own `ServiceUnavailable`, encoded by hand, and each binding repeated `error: ProviderUnavailable` so its clients decoded it, which nothing tied to the verifier; mapped to a refusal instead, an outage was a 401 that signed the caller out. The errors sit on the descriptor, not the binding, as the verifier, which fails with them, is the descriptor's, and every surface naming the descriptor declares them at once. Rejected: declaring them as the security middleware's native `error`, which `HttpApiEndpoint` already merges into each endpoint's: the binding adds them to protected endpoints itself, as it adds its own, so the status rule, the projected order and the written client types are the ones every other error has. Over MCP such an error is the endpoint's HTTP answer, before any tool runs, so `Testing.mcpClient`, which knows no descriptor, fails with an `McpCallError` naming its status and body. Lost: a verifier's own headers on a failure, which no consumer set.
