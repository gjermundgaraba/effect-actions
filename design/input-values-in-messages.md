# Input values in messages

A message for input that does not decode never carries a value of the input, nor does an `InvalidInput`'s `issues`: every surface formats Effect's schema issues with `reportInput` off, its default, so a message names expectations and each issue's path where Effect's decoder reports one, and a test pins each surface. No option turns it on. A path names the keys it passes through, a record's included, so a record keyed by an email names the email. Over HTTP, `HttpApiBuilder` decodes a payload through a union of its schemas, which reports a wrong or missing top-level literal field as the whole expected shape. Effect CLI's own parser, which reads a flag before the schema decodes it, names a rejected choice, an unknown flag or an unexpected argument as typed, to whoever typed it; keeping it out would take the parser's messages over, or no choice flags. A custom message is the schema's author's, sent as written. Effect's `Toolkit.handle`, which MCP calls too, records a call's raw arguments on the current span; the library leaves that native, and guarantees.md states it.
