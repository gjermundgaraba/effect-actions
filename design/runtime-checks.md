# Runtime checks

A surface checks what it is given when it is called, not in the types: `ActionHttp.layer` refuses implementations holding none of its binding's actions, and `ActionMcp.layerHttp` and `runStdio` input that is not one object with keys, each refusal naming the actions. Rejected: type checks for both, a property named after the rule that a key distributed over the arguments demanded, which duplicated a refusal made at startup before anything is built and cost helpers their natural form: a list holding the helper's type parameter beside another implementation, `[app, double]`, as 0.8.0's `Http.layer` took it, or a binding the helper makes from generic actions, left the key deferred and demanded the refusal's property, so the docs listed the forms that compiled. On MCP, erased input and an argument chosen by a condition passed the types to the native refusal, a defect when the layer builds whose message suggests `Tool.EmptyParams`; the library's own check reads the JSON Schema the native server reads, names the actions and runs first. The types still check what reaches a handler and what a surface owes.
