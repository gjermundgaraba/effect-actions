# Authentication descriptor and provider

`Authentication.make(name, identity, { security })` is a browser-safe declaration of one native scheme, which bindings and MCP endpoints name, and `Authentication.layer(descriptor, verify, { protectedResource })` its server-only provider, built once per layer graph. Each protected endpoint carries the descriptor's native security middleware, so one layer mixes public and protected actions and authenticates each protected request before its body is read. This reverses the earlier authentication as middleware, where `make` returned an `HttpRouter.Middleware` provided around layers: what it covered depended on where the host provided it ("Contract identity"), and public and protected actions took separate layers. The security middleware's identifier is the descriptor's own: shared with the provider, a host listing it in a layer's `middleware` compiled and failed to build. A host's own route takes `Authentication.protect(descriptor)`, the router middleware an MCP endpoint takes, and answers as an action's route does. Rejected: `bearerToken`, from which, with the verify function and `refusal`, every host rebuilt that answer: the clankerauth SDK and four applications each did, the SDK's rebuild with no `no-store` on success and no challenge on a route's own 401. `bearerTokenOf` stays for a caller the router never routes. Middleware feeding the verifier, such as a tenant resolved per request, is router middleware provided in a later `Layer.provide` than the authentication; middleware reading the identity is `ActionHttp.layer`'s `middleware`, native `HttpApiMiddleware` inside authentication and outside decoding, failing only with the binding's `error`, since clients decode only what the binding declares; a failure callers see after decoding, on every surface, is a handler's ("Limits"). It sits on the layer, not the binding, which browser clients import. Rejected: refusing every middleware error, which blocked a limit keyed by the caller that also counts input that does not decode, which neither a handler nor router middleware can be. Not fixed, documented: `Layer.provide([authenticate, tenant.layer])` as one array leaves the verifier's service owed, since an array's members do not provide to one another. Rejected: carrying the verifier's per-request `R` on the provider's type, which the routes, built before the verifier, could owe only if the browser-safe descriptor declared it, a new concept to save one wiring order. Not built: identity-reading middleware on MCP, and a hook observing the call's `Exit` or a request scope shared by both remote adapters, which wait for a concrete need; the only consumer, a caller log, sets an HTTP header.
