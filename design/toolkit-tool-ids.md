# Toolkit tool ids

A Toolkit tool's `id` carries the key of its implementation's handlers' memoized layer, which each `implement` makes, because Effect finds a tool's handler by its `id`: a `make` call's `layer` serves any `toolkit` of the same implementations whose tools it serves, one of fewer `actions` included, while two implementations with tools of one name, such as one action behind two authorizers, never run each other's handlers. Rejected: a key per `make` call, which separates nothing its implementation does not, since the authorizer is stated in `implement`; a toolkit and a layer of one implementation from two `make` calls type-checked, as `Tool.HandlersFor` is keyed by name, and died on the first call, so toolkits made per agent or per approval policy could not share one handler layer. Lost: two layers of one implementation, built apart with different services and provided together, each serving its own toolkit; separate services take separate implementations. Also rejected: the authorizer's layer's key in the id, which told apart nothing the handlers' did not.
