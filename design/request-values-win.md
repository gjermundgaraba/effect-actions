# Request values win

A request's own value wins over a startup value under the same tag, on every surface. `HttpApiBuilder.group` and `McpServer.registerToolkit` apply the context they are built in on top of each request's, so `ActionHttp.layer` builds its group in an empty context and runs its routes over `Context.merge(startup, request)`, without the layer's `Scope`, and `ActionMcp` registers its toolkit with only the registry and the tool handlers. Both rely on those functions reading nothing else from their build context: a service they start to read fails the layer build, but a reference would silently take its default. The merge wraps the whole route, so `HttpApi`'s own error reporting runs once, in the merged context. A protected action's identity is the exception ("Contract identity"): only its descriptor's provider gives it, and the types refuse any other, a startup value or `HttpRouter.provideRequest` included; over MCP it is promoted at tool entry, never on a local call. Rejected: re-applying the identity inside the shared dispatch, under which a Toolkit call a handler makes under a narrower identity would run as the signed-in caller.
