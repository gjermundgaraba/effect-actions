# Handler requirements

`implement` infers what each handler owes into one map, `RequestServices`, reverse-mapped from a list's record key by key (`Several`), and `R` for one action's handler, so a handler is typed from its contract however it is written, unless its builder reaches `implement` through `.pipe(...)` or an overloaded wrapper such as `Effect.withSpan`: TypeScript gives the Effect before `.pipe` no contextual type, and types an overloaded call's arguments from its first overload. Rejected: inferring the record whole, as `H`, and checking it afterwards (`Exact`), where a generic handler, such as one `Effect.fn` makes, took an `any` input, which 0.8.0's `group.implement` had typed. `NoHandler<R>`, stating that a list takes no single handler, must stay a named alias, whose type arguments keep TypeScript's mark that they are not yet inferred, where `never` or the same object type written inline becomes a real candidate and a builder's record loses its contextual types. For the reverse reason, one action's handler and a built authorizer stay written out rather than `Handler<T, R>` and `Authorize<A, RA>`: an alias carrying `R` or `RA` before they are inferred bears that mark as a whole, so an `Effect.fn(...)` returned there takes an `any` input or action. One action's `RequestServices` is constrained to `never`, so a record keyed by its name is refused. Cost: instantiations superlinear in a record's size; measured on TypeScript 7.0.2, one `implement` of 60 actions adds 59k instantiations (25k before), of 150 adds 255k (62k), of 300 adds 869k (124k) and 0.2 s. Lost: a record's handler may be inferred to owe `unknown`, where a generic call returning it takes its entry of `RequestServices`, not yet inferred, for a type parameter no argument gives, as `Effect.catchTag`'s data-first overload does for the `orElse` handler's services; `catch`, `map`, `orDie`, `flatMap`, `mapError`, `Effect.gen` and one action's handler do not. The surface then owes `Request<"Requires", unknown>`, an error at launch naming no handler, and the remedy is documentation, the Action card's failure mode: write that Effect with `.pipe(...)`. Rejected, as neither the arguments nor the result can say more: a rest parameter typed from `RequestServices`, which made TypeScript infer `unknown` for every record, 75 errors across the tests and specs; `Several` testing its own entry, which loses the reverse mapping that types each handler; and a label in the result type naming the handler, since `unknown extends RequestServices` stays unresolved for a generic `RequestServices`, so a helper taking a handler and the layer that provides it could no longer discharge its requirements.
