# Contract fields

A contract's fields say what the library does with them. `caller` names who may call, `Action.Anyone` or an identity service, where `auth` read as authentication or authorization, beside `authorize` and the `Authentication` module. `Action.Anyone` is an exported `unique symbol`, `Symbol.for("@gjermundgaraba/effect-actions/Anyone")`, in place of the string `"public"`: a value the editor completes and documents, which two copies of the package agree on, as they agreed on the string; `Action.public` cannot be an export, `public` being reserved. Still required: an action that names no caller fails to compile and throws, rather than being public ("Contract identity"). `readOnly: boolean` replaces `access: "read" | "write"`, which read as access control though it enforces nothing. It stays a required fact of the operation, not of MCP: an authorizer reads it, the clankerauth SDK's requiring the write scope for every action that is not read-only, MCP's `readOnlyHint` is it, and spans and logs carry it as `action.read_only`, so what a tool tells a client and what an authorizer enforces cannot disagree. `make` refuses any other value at run time, as it refused a third access. `hints` becomes `mcp`, in MCP's own names, `title`, `destructiveHint`, `idempotentHint`, `openWorldHint` and `_meta`, and the contract keeps them as given. A per-action option of one surface goes on the contract when every endpoint and client of the action must agree on it, as `mcp` does, since every MCP endpoint and the Toolkit annotate their tools from that one field, and on the surface when only that surface reads it, as the CLI's `commands` and the Toolkit's `needsApproval`. This reverses the unreleased 0.10.0's rename of 0.8.0's `mcp` to `hints`, made because a native Toolkit's tools carry them too: only Effect's `McpServer` reads them, and `LanguageModel` never sends them to a model, so the name said where they matter, and invented names and defaults beside MCP's made a reader translate both. Native `Tool.Destructive`, `Tool.Idempotent`, `Tool.OpenWorld`, `Tool.Title` and `Tool.Meta` are annotated only where given, so a hint left out is Effect's default, MCP's, but a read-only action's `destructiveHint`, which is `false`: Effect always lists the four hints, and its default would call every read destructive. A given value passes through, as MCP calls `destructiveHint` and `idempotentHint` meaningless on a read-only tool; this drops the type rule refusing `destructive` on a read and its run-time override, which refused nothing for `idempotent`. `mcp` refuses `readOnlyHint`, the contract's `readOnly`. `Action` imports nothing of `effect/ai`, so a contract stays browser-safe; `tests/mcp-types.spec.ts` pins `Action.Mcp` to `McpSchema.ToolAnnotations` and `McpSchema.Tool`'s `_meta`. Rejected: `readOnly` as `mcp.readOnlyHint` alone, an authorizer then reading an MCP hint; dropping the field for an annotation each application defines, which states the same fact twice, once as the hint; `caller` left out for a public action, which fails open; and `Action.Public`, which keeps the word `auth: "public"` made ambiguous.
