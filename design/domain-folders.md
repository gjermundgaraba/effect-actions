# Domain folders

Source and tests are grouped by domain, not by visibility or mechanism. `src/contract/` holds `Action` and what every surface shares; `src/authentication/` holds `Authentication`, its provider and its refusals; each surface (`http`, `mcp`, `rpc`, `toolkit`, `cli`) and `testing` has a folder holding its public module beside the private code it owns; `src/stdio/` has none, and holds the stderr console of the two programs whose stdout carries data, an MCP server over stdio and a CLI command, neither of which owns the other's. A PascalCase file is a package subpath; a lowercase one is private, and `package.json` exports none of them. Tests mirror the folders, with the suites of rules every surface keeps in `tests/guarantees/` and what is not a suite in `tests/support/`. A domain may import another's private module, as MCP serves the Toolkit's tools (`toolkit/tools.ts`) and a remote CLI command calls an HTTP binding through `http/client.ts`, but never another surface's public module, and `src/contract/` imports nothing outside itself; source imports source by relative path, never by the package's name, which resolves to source too. `no-restricted-imports` in `vite.config.ts` reports all three at the import, where a list of the allowed imports would drift; it replaces a test that read the import specifiers with a pattern of its own and saw only relative ones. This reverses the flat `src/<Module>.ts` beside one `src/internal/`, where a surface's code sat in two places and `internal/tools.ts` named a mechanism. The pack entries are the PascalCase files `vite.config.ts` finds, and with `devExports` the repository's `package.json` exports point at them, so TypeScript, Vitest and tsx resolve the package's own name to source, the examples import it as a consumer does, and `publishConfig.exports` carries the build's for `pack` and `publish`. Lost: an import across domains shows where `internal/` hid it. Rejected: domain folders under `src/internal/` beside flat public modules, which still splits each surface in two; and an Effect service with `make` and a static `layer` for each private module, since they are functions, `SteppedUpRefusal` is a slot each request fills, and the HTTP middleware tags keep their server layers apart so a client's bundle leaves them out.
