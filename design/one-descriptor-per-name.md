# One descriptor per name

A server builds its HTTP binding and its `Authentication.layer` provider from one descriptor value, and `ActionHttp.layer` dies when it builds unless the binding's descriptor is the very value the provider was built from. The routes decode a credential with the binding's native security middleware and declare the binding descriptor's errors; MCP and `protect` decode with the provider's scheme and answer its verifier's errors. Two descriptors of one name share the provider's name-keyed service, so nothing else tells them apart: a browser's static cookie descriptor served with a provider built at startup from the deployment's cookie name read one cookie on the routes and another on MCP, and a provider declaring an error the binding does not answered with a status no route declared. Identity is the rule bindings already follow for actions, which serve only the very values they hold. It costs a server whose scheme the deployment decides building its binding at startup from the descriptor it gives the provider, and refuses a descriptor built twice from the same options. Rejected: comparing the two descriptors' schemes, which needed per-kind rules tracking Effect's decoders (an HTTP scheme's name and a header key's case) and still let the declared errors differ.
