# CLI console

What a command runs, from its builder to its codecs, gets the console `runStdio` gives its program, since a CLI's stdout carries data as a stdio server's does: every logger and `Console` method writes to stderr, `Logger.consoleJson` and `Console.log` included, which `Logger.LogToStderr` does not move. `runMain`'s report of a defect or a failed host layer, and those layers' logs, fall outside it, on stdout, so `ActionCli.onStderr`, applied last before the stock `runMain`, provides `Logger.LogToStderr` around the program, so the default logger of the layers within writes to stderr; it reports there what `runMain` would, and exits as `runMain` would have. Without it every scripted CLI carried three steps, and one missing any of them still compiled and wrote to stdout. The library adds no runner, which would compete with Effect's, and `ActionMcp` no alias: an MCP subprocess imports `onStderr` from `ActionCli`. Lost: a custom `teardown` or an outer handler of defects sees a value marked reported rather than the cause. Rejected: wrapping each command, which reaches neither `runMain`'s report nor the host's layers; a layer the host provides outermost, which `runMain`'s report runs outside of; a stderr `Console` around the program, which would move `--help` off stdout; and marking the host's own error reported, which "CLI failures" rejects. The console promises only that every method writes through `error`, counters and timers keeping their counts and start times; Node's warnings, group indentation and trace layout, which 3a4275c reproduced in about sixty lines and a documented list of deviations, are not rebuilt, as no stdio server or CLI needs them.
