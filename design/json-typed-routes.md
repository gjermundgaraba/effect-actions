# JSON-typed routes

`ActionHttp` routes take only JSON-typed requests. The same route middleware answers a request without a content type with 415 before `HttpApi`'s default reads it as JSON, so every POST a page can send without a CORS preflight (no type, `text/plain`, the form types) is a 415, and cookie credentials cannot drive a cross-site write. Each endpoint pins its payload to JSON with `HttpApiSchema.asJson()`: an input annotated with another encoding made `HttpApi` take that type, a form body answered 200, where no other surface reads the annotation. Refusing such an input at `make` was rejected: a contract every other surface serves would be one HTTP could not bind, for an annotation HTTP alone reads. As on the MCP endpoint, the check runs after the middleware around the layer, and on a protected route after authentication, so a request without a credential is a 401 before a 415 or a 400: authentication reads no body.

Every route is a POST, a `readOnly` action's included. A GET carries its input in the query string, where `HttpApi` takes only fields that encode to strings or arrays of strings, so a nested input, or a number a query would carry as text, has no faithful GET form, and one binding would map actions two ways. What a GET would buy is caching, and a protected route's answers are `no-store` anyway: only a public `readOnly` action gives it up.
