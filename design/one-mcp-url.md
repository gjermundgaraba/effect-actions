# One MCP URL

An MCP endpoint serving public and protected tools serves both on one URL, signed out and signed in. A gate decides before the native server reads the body, from the routing headers Effect checks against the body, compared as they are, so a Base64-encoded name names no public tool. It is an allowlist: `server/discover`, `tools/list`, `notifications/cancelled` and a public tool's call pass without a credential, and one they present is verified, as MCP authorization answers an invalid or expired token with 401 so a client signs in again, where an HTTP public route, which carries no security, ignores it; every other request is authenticated, failing closed on a missing or unreadable name. Rejected: admitting every method without a routed name, which reached a protected prompt's completion callback and a protected resource's subscription. This reverses the earlier documented pattern of `examples/mcp-sign-in.ts`, which 83117ee removed, an optional identity and a hook refusing a signed-out caller, which opened listing and decoding of protected tools to signed-out callers and served any implementation whose hook did not refuse them. It takes up the header-selected preflight 56b2459 dropped: Effect now refuses a stateless request whose headers disagree with its body, which makes the headers safe to decide on. Rejected: optional identity, `caller: Optional(CurrentActor)` or an `Option`-valued service, since a public and a protected action per need covers it. Lost: a public action that personalizes when signed in, and a public resource or prompt on a mixed endpoint. Signed-out callers list every tool; public tools on an endpoint of their own keep the protected ones unlisted. An empty credential, such as `Authorization: Bearer`, passes as none, as the scheme's native decoding gives it, where a check of the raw header refused it with 401.
