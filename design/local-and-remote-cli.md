# Local and remote CLI

`ActionCli.command` and `make` take implementations and run them in process; `ActionCli.remoteCommand` and `remote` take an HTTP binding and call its server. Each has one signature. This reverses 4431b09, which merged `ActionCliClient` into `ActionCli` (0.10.0), so `command` and `make` each took either target: three overloads apiece, the binding's, the implementations', and a last catch-all taking either, there only because TypeScript reports a call matching no overload by the last one's error alone; a target chosen by a condition between a binding and implementations reached the catch-all, compiled, and owed `unknown`, which only `runMain` refused; and at run time a structural check, a binding's `api` property, told the forms apart. The two forms already took different options, `client` only from a binding, which the local form refused at run time too; now the types refuse it, from a variable as from a literal, since `command` and `remoteCommand` check their options for unknown keys as `make` and `remote` do, so a command meant to call a server never quietly runs in process. Split, every mistake is reported against the signature called, a conditional target is a compile error at the call, the fix as before a command built from each and chosen between, and nothing at run time asks which form it was given. Cost: two more exports, and a host offering both builds both by name. Rejected: keeping the merged functions and dropping only the catch-all, under which TypeScript reports a mistake in one form, such as a misspelled `commands` key, as the failure to match the other.
